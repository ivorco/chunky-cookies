# agents.md — chunky-cookies

Guidance for AI agents working on this repository.

## What this project is

`chunky-cookies` is a small TypeScript library that transparently splits large cookie values across multiple cookies to bypass the 4 KB browser limit. It is framework-agnostic at its core, with optional adapters for Zustand and Next.js.

## Project structure

```
src/
  core.ts           Pure chunking logic — setItem, getItem, removeItem, CookieWrapper
  index.ts          Public re-exports (single entry point)
  wrappers/
    js-cookie.ts    CookieWrapper backed by js-cookie (client-side)
    next.ts         CookieWrapper backed by Next.js cookie APIs (server-side)
  adapters/
    zustand.ts      cookieStorage() — Zustand persist adapter
tests/
  core.test.ts      Unit tests (Vitest, in-memory CookieWrapper mock)
examples/
  standalone.ts
  with-zustand.ts
  with-nextjs-middleware.ts
  custom-wrapper.ts
```

## Key design rules

- **`core.ts` has zero runtime dependencies.** Do not import js-cookie, next, or zustand there.
- **Zustand, Next.js, and js-cookie are all optional peer dependencies.** Do not add any of them as regular dependencies.
- **The `CookieWrapper` interface is the extension point.** Any new backend (e.g. `document.cookie`, a test mock, a session store) must implement only `get`, `set`, and `remove`.
- **Never scan chunks with a `while` loop.** Always read and remove exactly `meta.chunks` chunks — this prevents stale data from a previous larger write from being appended. This is a known past bug; do not reintroduce it.
- **`MAX_CHUNK_SIZE = Math.floor(4000 / 3)` — do not change this constant** without updating the tests and documenting why. The 1/3 factor accounts for URL-encoding overhead where characters like `{`, `"`, `:` can triple in size.

## Running tests

```bash
npm test          # vitest run (single pass)
npm run test:watch  # vitest in watch mode
```

All tests live in `tests/` and use an in-memory `MemoryCookieWrapper` — no browser, no DOM, no js-cookie needed.

## Adding a new wrapper

1. Create `src/wrappers/<name>.ts`
2. Implement `CookieWrapper` from `../core.js`
3. Export it from `src/index.ts`
4. Add a usage example in `examples/`
5. Add tests in `tests/` using the in-memory mock pattern as a guide

## What NOT to do

- Do not add a build step to examples or tests — they are for documentation and development only.
- Do not commit `dist/` — it is generated by `npm run build` and is gitignored.
- Do not change the public API (function signatures, interface shape) without a semver major bump.
- Do not add a dependency that would pull in a runtime package into `core.ts`.
